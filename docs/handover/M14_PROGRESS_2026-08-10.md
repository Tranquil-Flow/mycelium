## Closed architecture gates

- The native Iroh sidecar retains outbound connections by endpoint and generation
  rather than reconnecting per frame. It publishes privacy-reduced direct/relay/
  unknown path class, cold and warm RTT, observed goodput, jitter, loss, reconnects,
  path changes, connection count, frame count, generation, and freshness.
- A strict `mycelium.transport_path_observation.v1` contract requires at least three
  acknowledged Router frames and proves reuse with fewer connections than frames.
  Unknown, stale, incomplete, duplicate, endpoint-mismatched, synthetic, or
  non-activation observations fail closed.
- All six ordered edges among the M4 Pro (`node-0`), Evis MacBook Pro (`node-1`),
  and Surface (`node-2`) were independently measured on the activation plane. Every
  edge was direct, carried four frames over one persistent connection, and reported
  zero loss.
- Exact directed-cycle search selected
  `node-0 -> node-2 -> node-1 -> node-0` at 42.104 ms under the documented
  `warm RTT / 2 + jitter` objective. The canonical node-id cycle cost 384.554 ms;
  the selected result therefore proves that measured asymmetric links can change
  physical order.
- The selected cycle is opened into the forward pipeline
  `node-0 -> node-2 -> node-1`, with an explicit decode loopback
  `node-1 -> node-0`. The physical runner now preserves this plan order instead of
  silently sorting node IDs.
- Nested capability-aware allocation assigns `[0,1)` to the M4 Pro, `[1,2)` to the
  Surface NumPy stage, and `[2,24)` to the Evis MacBook. The execution graph, staged
  assignments, and live successor bindings all carry that same order.
- Durable membership now has an explicit vendor-neutral `linux_numpy_iroh` runtime
  class. Three fresh, activation-eligible members are bound to the full endpoint IDs
  used by the measured matrix. Linux node supervision supports descriptor-pinned
  artifact launch and hardened procfs configurations that hide ancestor executables.
- Plans, Network, Nodes, and Readiness consume one strict
  `mycelium.m14_topology_projection.v1`. The UI exposes ring, SCC, elastic, and true
  map views; exactness and rejected cycles; physical versus logical edges; allocation;
  connection reuse; and an edge inspector with pricing substitution and evidence
  digest. Unknown physical location is shown explicitly rather than invented.

## Exact non-claims and next gate

M14 prices a frozen, fresh directed matrix and proves one selected three-host route.
It does not yet continuously re-optimize a serving deployment, claim relay behavior
without observing a relay, provide geolocation, use NumPy stage-local KV, or claim
that the tiny one-layer NumPy placement improves throughput. M15 makes prefill/decode
and workload scenarios explicit planning objectives and compares robust/Pareto plans.
