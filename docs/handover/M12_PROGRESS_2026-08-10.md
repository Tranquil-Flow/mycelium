## Evidence-spine continuation

The read-only product spine now persists its bounded privacy-reduced event window in
the owner-only seed state root. Restart validates and restores the last complete event,
publication generation, and cursor before publishing again. Writes are bounded,
atomic, mode `0600`, fsynced, and reject a missing/unsafe/replaced root or corrupt,
oversized, discontinuous state. Source failures degrade independently and a mixed
qualification/deployment/model/topology binding withholds the coherent qualification
relation and readiness.

The physical route now exposes a private in-process assignment adapter sourced from
the same refreshed, signed assignment offers and validated execution graph used for
startup. The product projector binds pseudonymous devices, stages, assignment digests,
stage-pack digests, load generations, and load-proof digests without adding those
fields to the public legacy live-route payload. Artifact inventory, runtime/KV
ownership, and request-lifecycle entity adapters remain explicitly `unsupported` in
source provenance instead of being silently implied by `supported_entity_kinds`.

The browser source uses bounded same-origin finite-SSE polling with `Last-Event-ID`,
strict closed decoding, cursor continuity, stale-cursor `409` snapshot recovery, and
last-valid-snapshot retention on disconnect. All eight direct routes consume or show
the same product snapshot in live composition. Network has independent logical and
physical controls; Nodes and Plans show assignment/load evidence; Readiness remains a
separate authority matrix; Incidents shows a bounded evidence timeline; every product

### Seed-authority rotation implementation

The non-physical rotation foundation is now implemented. Authority metadata carries a
monotonic generation starting at 1. `rotate-begin` creates a new owner-only key and a
canonical transition signed independently by both the old and new keys; the record
binds swarm, seed node, old/new digests, generations, effective time, bounded overlap,
and operator reason. `rotate-complete` atomically promotes the database generation and
then finalizes the key filename. Loaders select the one allowed private key whose
public digest matches committed database metadata, so a crash after the database
commit but before the rename remains recoverable without trusting the wrong key.

The seed HTTP service exposes the dual-signed transition, pinned clients verify it
under the old trust root, and both old and new seed signatures are accepted only in
the bounded overlap. After expiry, the old digest is rejected. The native node agent
fetches the transition before join and before each heartbeat and installs the verified
endpoint/digest pair into its membership session. Backup manifests now bind the exact
authority generation. The new transition and operator-rotation protocols bring the
contract registry to 44 executable fixtures.

This code has not yet rotated the live generation-3 authority. Live promotion remains
withheld until rotation state is projected into Incidents/Readiness and a two-Mac
maintenance proof shows that both existing members learned the transition before
completion. The operator has explicitly deferred, not passed, the different-LAN Mac
and Android/Termux physical gates.

The projection blocker is now closed in source. Before rotation begins, the operator
persists the exact pre-rotation product pseudonym salt as a separate owner-only
32-byte identity component. Live loaders require that component after authority
generation 1, while generation-1 roots remain load-only compatible by deriving the
same legacy value. Backups bind its digest and restore its exact bytes; older
generation-1 backups remain restorable by deterministic derivation. A rotation test
proves the seed digest changes from authority generation 1 to 2 while the product
pseudonym salt remains byte-for-byte stable.

The privacy-reduced product snapshot now adds `authority_generation` beside each
member generation and emits `seed_rotation_pending` or `seed_rotation_completed` as
an incident/notice without exposing either key digest. Nodes renders both generations;
Incidents consumes the same closed snapshot. Live physical promotion is still
withheld until the existing two Mac agents are restarted onto the overlap-aware build
and acknowledge the transition in a measured maintenance run.

That acknowledgement is now fail-closed rather than inferred from a heartbeat. Each
node signs `mycelium.membership.seed_rotation_ack.v1`, binding its current member
generation and incarnation to the canonical transition digest and next authority
generation. The seed persists one acknowledgement per member/authority generation;
replayed, stale-generation, or wrong-transition messages fail. `rotate-status` reports
the acknowledged member IDs and generations, and `rotate-complete` refuses promotion
while any fresh activation-eligible native member lacks the exact acknowledgement.
This brings the executable boundary-contract registry to 45 protocols. The live
two-Mac maintenance proof remains open until both agents run this build and the
operator captures the durable acknowledgements before key promotion.
