## 1. Goal

One sentence: **a human types an arbitrary prompt into the browser and watches tokens stream back, generated by a model split across the M4 Pro and the Lenovo.**

That is the entire MVP. Everything else is a later layer.

## 2. Why the previous plan stalled

Measured facts about the repository as of `533d107`:

| Metric | Value |
|---|---|
| Project Python, non-test | ~86,000 lines |
| Test Python | ~85,000 lines across 206 files |
| Markdown design docs | 315 |
| Commits | 284 over ~3 weeks |
| Browser prompts served end-to-end | 0 |

The distributed inference itself is **not** the blocker. Run `w8-mvp-live-533d107-20260809t091035z` performed real cross-host M4↔Lenovo inference over Iroh and produced exact token parity (`[4599,3329,2506,5145]`). The wire works.

What blocked the product was that every increment had to satisfy a ~9,000-line qualification / frozen-evidence / sealing pipeline before it could be considered real, and the physical controller was one-shot: it ran a fixed challenge, snapshotted, and tore everything down. There was no way to hold a route open and send a second prompt through it.

## 3. The key structural finding

The previous handover proposed adding "an injectable request backend" to the gateway. **That injection point already exists.**

`mycelium_request_gateway` is built entirely on three Protocols:

```python
# mycelium_request_gateway/backend.py:22
class PromptCodec(Protocol):
    def encode(self, prompt: str) -> tuple[int, ...]: ...
    def decode_token(self, token_id: int) -> str: ...

# mycelium_request_gateway/backend.py:26
class RouterPort(Protocol):
    def current_deployment(self) -> ExecutionGraph: ...
    def admit(self, request: RequestContext, client_sink: object, *,
              pinned_deployment: ExecutionGraph | None = None, **kwargs) -> str: ...
    def decode_one(self, request_id: str) -> bool: ...
    def request_status(self, request_id: str) -> str: ...
    def cancel(self, request_id: str) -> bool: ...

# mycelium_request_gateway/qualification.py:12
class QualificationSource(Protocol):
    def current(self) -> RouteQualificationV1 | None: ...
```

`create_request_gateway_application(...)` takes all three by injection. Likewise, the node lifecycle object the handover asks to "extract" largely exists already as `NodeProcessSession` (`physical_inference_qualification.py:444`) — it is simply imprisoned inside the 1,300-line `QualificationController`.

**Consequence: the MVP is three implementations of existing protocols plus one supervisor. The gateway, the router, and the React app are not modified at all.**

## 4. Architecture

```
Browser — existing React app                        UNCHANGED
        │ HTTP + SSE
mycelium_ui_gateway                                 UNCHANGED
        │
mycelium_request_gateway                            UNCHANGED
  create_request_gateway_application(...)
        │
   ┌────┴───────────────┬──────────────────────┐
RouterPort          PromptCodec         QualificationSource
   │                    │                      │
LiveRouterPort     GPT2PromptCodec       RouteHealthSource
   │                (real GPT-2 BPE)     (liveness, not sealed evidence)
   │
LiveRoute — open() / infer() / close()
   │  owns two NodeProcessSession instances, stays alive between requests
   │
M4 Pro node-0 (MLX)  ←─── Iroh ───→  Lenovo node-1 (NumPy)
```

### `LiveRoute` interface

```python
class LiveRoute:
    def open(self) -> RouteIdentity:
        """Launch both nodes; hello, configure, start. Idempotent-fail: raises on
        partial bring-up after cleaning up whatever did start."""

    def infer(self, token_ids: Sequence[int], *, max_new_tokens: int,
              request_id: str, sink: TokenSink) -> InferenceResult:
        """infer_start then repeated infer_decode. Emits each token to sink as it
        is produced. Does NOT tear down the route on completion."""

    def counters(self) -> RouteCounters:
        """Per-node frames sent/received, applied_operation_count, fatal flag."""

    def is_alive(self) -> bool:
        """Both node processes running, no fatal transport error observed."""

    def close(self) -> None:
        """stop, process close, cleanup on both hosts. Safe to call twice."""
```

Invariants:

- The route stays open between requests. Only `close()` or a fatal error tears it down.
- Any node exit or transport fatal makes `is_alive()` false permanently — no self-healing in MVP.
- Credentials pass via files and pipes, never command output or argv.
- No silent fallback. If the route cannot serve, the request fails with an explicit code.

### Readiness: `RouteHealthSource`

The gateway's `QualificationGate` type-checks `RouteQualificationV1` and compares ten binding fields, so `RouteHealthSource.current()` must return a genuine record. MVP constructs it from the **live startup challenge** — real endpoints, real model manifest digest, real stage-load proofs taken from the actual `configure` responses — signed with a session-local key rather than routed through the frozen-evidence sealer.

Identity binding stays exact and real. Only the archival ceremony is skipped.

This makes drop-on-kill trivial: the supervisor stops publishing, `current()` returns `None`, and the gateway answers `route_dropped` without any new code in the gateway.

Historical sealed evidence and live readiness remain different concepts, as the previous handover correctly insisted. This design enforces that separation by construction: nothing in the serving path reads a stored `route_ready` file.

### Startup challenge

At `open()`, before publishing readiness, the supervisor runs the known fixed prompt through both nodes and requires exact expected token IDs, frames observed in both directions, zero active state, and no fatal transport error.

**A fixed token sequence is permitted only here.** It is never returned as the response to a user prompt. The M4 acceptance gate enforces this.

## 5. Milestones

Each milestone is independently demoable and independently committable.

### M0 — Seam proof (today, morning)

Real browser, real prompt box, real tokenizer, real gateway, real SSE streaming. `LiveRoute` is a test double that returns deterministic tokens.

The UI labels this `SIMULATED ROUTE`, and the M4 acceptance gate rejects it.

**M0 is not a demo of distributed inference.** It exists so that M1 is an implementation swap rather than a debugging session. Do not present M0 as the product.

Done when: a prompt typed in the browser streams decoded tokens from the real tokenizer through the unmodified gateway.

### M1 — First live prompt (today, target)

`LiveRoute` against the real M4 Pro ↔ Lenovo route. One arbitrary prompt, not present in any source file or fixture, crosses the physical route and streams real model output to the browser.

Done when all hold in one session:

1. Both workers start and load real DialoGPT-small shards.
2. Iroh transport established between distinct endpoints.
3. Startup challenge passes; readiness published.
4. React UI shows live readiness, not fixture readiness.
5. An arbitrary prompt returns model-generated decoded output in the browser.
6. Physical frame counters increased during that request.

**This is the demo.**

### M2 — Persistence

A second, different prompt reuses the same open route with no restage. Frame counters increase again. Route identity is unchanged between the two requests.

### M3 — Honest failure

Killing either worker drops readiness immediately and disables submission in the UI. Shutdown removes worker processes, socket and key material, and staging roots on both hosts.

### M4 — Acceptance gate

An executable, separately-marked test that submits two arbitrary prompts, records prompt hashes, request IDs, token IDs, decoded text, and before/after frame counters; asserts counters increased; and **fails if any fixture identifier appears in a live response**. Then kills the Lenovo worker and asserts the third request cannot reach the backend.

This is the test that makes "no canned output" a property of the build rather than a promise in a document.

## 6. Non-goals for MVP

Deferred until M4 passes:

- Third host, Surface, Pixel
- Cancellation qualification (return explicit `unsupported` if not genuinely implemented)
- Multibrowser release gates, Firefox/WebKit
- Fixing the stale `complete_context_replay` evidence validator (previous handover Tasks 1–2) — real work, but it gates archival sealing, not serving
- Re-sealing the historical run as provenance
- Any new frontend surface
- Public deployment

## 7. Layer 2 and beyond

The named follow-on features land behind seams this design already establishes:

| Feature | Where it lands |
|---|---|
| Add a peer to the swarm | `LiveRoute` grows from a fixed pair to an N-node execution graph; `RouterPort` unchanged |
| Change model type | `GPT2PromptCodec` becomes one implementation of `PromptCodec`; stage packs gain a model parameter |
| A genuinely useful model (Qwen-class) | Same seam as above, plus new shard layout and MLX/NumPy parity work |
| Re-enable sealed evidence | `RouteHealthSource` gains a sealer collaborator; serving path still does not depend on it |
| Recovery / replanning | `LiveRoute.is_alive()` becomes recoverable rather than terminal |

None of these require reopening the gateway, the router, or the React app.

## 8. Risks

| Risk | Mitigation |
|---|---|
| **Staging over a 122–256ms link is the long pole** — ~354MB, stage roots were deleted at shutdown | Start staging immediately, in the background, before writing M0 code |
| `RouterPort.admit` expects a real `ExecutionGraph` | Reuse `execution_graph_from_document` (`physical_inference_node.py:109`); the physical route already carries one |
| Hoisting `NodeProcessSession` out of `QualificationController` disturbs the 75-test physical controller suite | `LiveRoute` composes `NodeProcessSession` rather than modifying it; controller keeps its own call path |
| M1 slips past today | M0 still lands, and M1 becomes a short next session — the slow part is transfer, not code |

## 9. Testing strategy

TDD throughout. The M0 `LiveRoute` double is what keeps the inner loop fast: unit tests for `router_port`, `codec`, and `health` never touch SSH. Real hardware is exercised only by manual M1–M3 runs and by the M4 acceptance harness.

Existing suites that must stay green: `tests/request_gateway`, `tests/ui_gateway`, `tests/demo`, `tests/physical_qualification`, and the UI Vitest suite.

## 10. Anti-patterns carried forward

Retained verbatim in spirit from the previous handover, because they were correct:

- Do not rerun the 354MB transfer after a Python-only change.
- Do not build another frontend.
- Do not use fixture qualification in live mode.
- Do not return challenge tokens as user output.
- Do not read `route_ready=true` from disk and call it live readiness.
- Do not broaden to three hosts before two-host arbitrary prompts work.
- Do not weaken identity, signature, cleanup, or transport checks to make a demo green.
- Do not silently fall back to local, synthetic, or deterministic output.

Added:

- Do not present M0 as a working demo of distributed inference.
- Do not begin any Layer 2 feature before M4 passes.
