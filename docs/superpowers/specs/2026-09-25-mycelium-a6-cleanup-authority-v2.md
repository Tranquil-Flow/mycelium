The case no longer requires a committed cutover. On the live product an unproven successor completion cleanup is refused before cutover, so the case now proves that shape. - one coherent terminal: `TERMINAL_BLOCKED`, exactly one gateway `failed` notice with code `request_cleanup_unproven`, bound to the successor attempt; no failover to a second successor, because the refused successor cannot be retired without a cleanup proof;
- consistent cleanup: the pre-cutover abort ended the coordinator request `failed` with zero stale reservations (`process_cleanup_complete == true`).

The only authorized count-layer state is `pre_cutover_abort_releases_reservations_successor_terminal_uncommitted`. The fault seam arms the router's A6 completion-cleanup hold before the source fault. The hold is inert unless the fault control arms it, and it is bounded to 30 s. The seam stalls the successor's peers while the hold is in place and releases it only after the stall, so the stall always lands before cleanup can be proven. Without the hold the seam refuses the case.
